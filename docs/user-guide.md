# 使用与开发指南 · 1.13.0

NeoForge **21.1.233** / Java **21**。1.13.0 新增 MPU6050、高度计、多通道近邻电机接口和完整驱动附录。烧录页提供可直接选择的 8 个内置 HEX 示例、本地文件选择器和右上角退出按钮。ADC、DAC、OLED 均通过独立模块和 GPIO 协议访问，整个 64 KiB XDATA 为普通 XRAM。

## 安装与烧录

执行 `gradlew.bat build`，将 `build/libs/embeddeddev-1.13.0.jar` 放进实例 `mods`，替换旧版本。客户端与服务端均须更新。

1. 放置 **51 单片机最小系统板**，空手右键打开。
2. 切换到 **六面端子**。东、南、西、北、上、下各有一张卡。点击「管理引脚 → 添加引脚」，在弹出的窗口中填写标号，选择用途和物理引脚，保存后在该面点击「应用」。
3. 回到「烧录与调试」，默认使用「内置示例」。点击示例名打开列表，选择后点「烧录 HEX」，再点「运行」。全部示例随模组打包，无需下载或输入路径；悬停和底部文字提示接线、地址及所需晶振。
4. 自己编译的固件：点击「内置示例」切换到「本地 HEX」，点「…」选择文件，也可拖入 HEX；原有路径输入仍可使用。
5. 开发板三个页面右上角的「×」可直接退出，烧录页操作行只保留运行、停止、复位和单步。
6. 烧录页显示当前 PC 对应的机器码和反汇编，以及后续三条指令的顺序预览。运行或单步时会刷新。OLED 画面在独立模块的窗口里查看。

新放置的主板六面均为 **未绑定**。接线配置不会被烧录、复位或停止清除；CPU 复位也不会清空独立 OLED 的显存。停止时主板和红石接口模块的红石输出归零，CPU/RAM 保留。

旧存档中没有接线配置的主板会显示「未绑定」，需要按实际电路重新配置。原固件仍会保存。以前的隐式 P1/P3 方向映射不再使用，旧主板中的内置 OLED 显存不再读取；OLED 方块原来保存的画面会迁移到模块自身。

1.1 版的六面接线会自动迁移。原 I²C 面转换为标号 `SDA` 和 `SCL` 的两个 GPIO 引脚，沿用原先选定的物理引脚。

## 生存模式制造

1. 在主世界新生成区块的 **Y=-56 到 Y=40** 找硅石矿或深层硅石矿，用石镐或更好的镐采出**粗硅料**。时运增加粗硅料掉落，精准采集保留矿石。也可以在工作台中心放木炭，上下左右各放一块沙子合成粗硅料。
2. 将粗硅料或完整硅石矿放进熔炉或高炉，烧成**硅片**。用铜锭、黏土球和红石粉无序合成两块**覆铜电路板**。
3. 用硅片、铁粒、金粒和红石粉做 **STC89C52RC**。再用另一片硅片、铁粒和金粒无序合成 **11.0592 MHz 晶振**。用 MCU、晶振、两块铜锭和一块覆铜电路板组装最小系统板。晶振随成品预装。

拾取对应材料后可在原版配方书查看摆法。按钮、LED、红石接口和其他外设使用同款覆铜电路板。6、11.0592 和 12 MHz 晶振可在硅片、下界石英和紫水晶碎片中任选一种作频率片。22.1184 MHz 晶振使用石英和金锭，24 MHz 晶振使用石英和紫水晶碎片，两者还各需一粒铁粒。

## 游戏内手册与晶振

用书、纸和红石无序合成 **手册**，主手或副手右键打开独立图文界面。旧手册物品也可继续使用。手册分为「入门、开发、模块、速查、附录」五类，共 **46 个双语条目**，覆盖全部芯片、模块和生存配方。条目以实验步骤、配方卡、接线图、寄存器表、故障排查和可复制的代码组织。

「开发 → 模拟量与外部芯片」说明 STC89C52RC 没有片内 ADC/DAC。1.10.0 删除虚拟 ADC/DAC，1.10.1 再删除 OLED 桥接，原设备地址均恢复为普通 XRAM。章节包含 PCF8591 接线、控制字、C51 程序和 ADC→DAC 实验。独立 PCF8591 通过 GPIO 软件 I²C 控制，48H–4FH 是总线地址，不占 MCU 内存窗口。

旧存档移除 ADC/DAC 引脚，保留其他 GPIO 的名字、通道、线组和连线编号。带旧模拟引脚的主板加载时会暂停，保留固件和 CPU/RAM；旧模拟线对会失效，可剪线回收后重接。原 `adc_mirror.hex` 已退役，直接访问旧 ADC/DAC 窗口的固件必须修改后再运行。

搜索框查找整本书的标题、正文、端子及地址。滚轮在左侧滚动目录，在右侧翻页；左右方向键翻页，`Ctrl+F` 搜索，`Home` 回到入门。右上角星标收藏条目，左下「书签」筛选；阅读位置和书签保存在当前实例 `config/embeddeddev-handbook.json`。配方从当前世界读取，兼容数据包修改；材料支持悬停提示，并可跳到对应手册条目。代码框可复制完整代码，长内容会随 GUI 缩放自动分页。

推荐学习路线：**第一盏 LED → 按钮控制 LED → 自由连线 → 数码管 / OLED → 温度探头**。代码与内容均为本项目原创；界面采用纸页、绿色装帧和原生物品插图。资源包可覆盖 `assets/embeddeddev/manual/zh_cn.json` 或 `en_us.json` 更新内容；`tools/generate-handbook.mjs` 生成内置双语手册。

开发板右上角的晶振槽连接背包，可放入 **6、11.0592、12、22.1184、24 MHz** 晶振。新板与旧存档的默认晶振为 11.0592 MHz。取下或换装会暂停 CPU，重新点「运行」即可继续。晶振随开发板及其掉落物保存。

## 六面接口

方向采用世界坐标。每组可以添加多个不同用途的引脚，标号最多 24 个字符。标号和物理通道在组内各自唯一，同一物理引脚可以在其他组复用。六面页顶部显示玩家当前朝向。

每个方向提供 **G1–G4 四组端子**，各组独立命名、配置引脚和拉线，标号在组内唯一。同一个方向可以分别用不同 GPIO 接两组 SDA/SCL、一个 DQ 温度探头以及 LED。进入「管理引脚」用线组按钮切换 G1–G4，右侧填写组名，一次应用保存这一面的全部四组。线卷瞄准各组接线点时，准星会显示所选方向、组名和引脚。清空某组的引脚会拆除该组的线并掉落线材。旧存档原有接线归入 G1。

**罗盘**可用一个原版指南针无序合成，也可在模组创造栏领取。指针指向世界北方，右键在操作栏显示当前朝向。

### 拉线连接远程设备

1. 在主板「六面端子」的任意一面配置引脚。运行 `examples/i2c_oled_hello.hex` 的例子可在**上端子**设 GPIO `SDA=P1.6`、`SCL=P1.7`。
2. 手持**绝缘线卷**，右键主板端子，再右键外设。瞄准主板顶面中央选上端子，瞄准顶面边缘或侧面选东、南、西、北，瞄准底面选下端子。准星下显示当前端子、引脚和预计耗线。
3. 单引脚可直接连接，多个引脚按标号匹配。缺少唯一匹配时，在配对窗口为外设的每个端子选择对面的引脚。例如把主板的任意 GPIO 配给 LED 的 `LED`，或将三个 GPIO 配给 DS1302 的 `CE`、`SCLK`、`IO`。主板的「接线一览」显示远端位置、通道和连接状态。
4. 每段同维度最多 **32 格**，用**接线柱**转角、延长或分支。空接线柱会继承第一次接入的端子排。潜行右键取消选点。手持**线钳**瞄准线段右键可拆线，破坏端子也会回收对应线段。铜锭和任意颜色的羊毛无序合成 8 单位线材，每段按长度向上取整消耗。

每组连通端子由一块主板的一个端子控制，可以分接多个外设。OLED、PCF8591 和环境传感器可共用 `SDA`、`SCL`。同总线有线设备地址冲突时，状态页会列出冲突地址。环境传感器与 PCF8591 默认同为 `48h`，潜行右键 PCF8591 可改到 `49h`。

线路随世界保存。两端和沿途接线柱所在区块加载时才会传输信号。旧存档的相邻连接照常工作，已接有线端子的外设走线路，有线引脚也优先于主板同一端子的本地红石。更改引脚的显示标号会保留连线，移除或更换已接引脚需要重新配对。

| 类型 | 可绑定对象 | 行为 |
|---|---|---|
| GPIO | P0.0–P3.7 | 读取或驱动数字电平，按标号连接外设或接入数字红石端子 |


STC89C52 本身没有 ADC/DAC，主板也不再提供虚拟模拟通道。端子绑定 P0.0–P3.7，GPIO 兼顾输入和输出；模拟量通过 PCF8591 的 SDA/SCL 接口处理。

- GPIO 输入遵循基本准双向端口语义：先将相应锁存位置 1 才能读入外部高电平。未绑定的输入引脚保持上拉。
- 多个数字输入绑到同一引脚时按线与处理。旧存档的本地数字红石引脚显示为 GPIO，原有方向和接线继续有效。
- 相邻的 OLED 和环境传感器会匹配接触面上的两个 GPIO 标号 `SDA` 和 `SCL`，匹配不区分大小写。固件通过 GPIO 位操作进行 I²C 通信。
- 同一组 SDA、SCL 可以配置到多个方向，让不同地址的模块共用总线。同地址 OLED 会镜像收到的数据。
- 一个模块贴着多块符合接线条件的主板时，按下、上、北、南、西、东的顺序连接第一块。
- 红石输入每 tick 采样，输出每 tick 提交，小于一个 tick 的软件脉冲不保证在世界中出现。I²C 模块信号在每次 CPU 写 GPIO 时处理，因此单 tick 内完成的 I²C 位操作也能工作。

### 红石接口扩展模块

直接贴在主板旁，继承主板该方向的接线配置。输入从模块周围除主板外的方向采样；输出转发该方向的数字信号。右键模块打开相邻主板，统一在主板的六面接口里配置，不再使用模块自身的循环引脚操作。

通过标准红石接口可以对接机械动力的离合器、红石链路及其他支持红石的组件，其响应方式由对应模组决定。红石接口只传递红石信号；如需设置紧邻创造马达的转速，使用独立的多通道电机接口，见[模块与驱动手册](modules-and-drivers.md)。

远程使用时，将红石接口放到目标设备旁，空手右键打开设置。贴着旧主板时可以潜行右键打开端子设置。选择**相对主板的输入或输出**，再选择面向设备的红石侧。数字输入/输出接 GPIO。数字输入把红石 0 读为低电平、非零读为高电平，数字输出为 0 或 15。模拟输入/输出使用独立 PCF8591。输出只驱动所选一侧，停止主板或断线后归零。

## 八段数码管模块

单个红色数字，由 **A–G 七段和 DP 小数点**组成。默认共阴，GPIO 高电平点亮；潜行空手右键切换共阳，改为低电平点亮。公共供电和限流由模块内部提供，只需连接八个信号端子。空手右键可查看共阳/共阴模式、点亮段码与连接状态。

在主板任一方向的一组端子中添加 `A、B、C、D、E、F、G、DP`，全部选择 GPIO。示例依次绑定 **P1.0–P1.7**，用绝缘线卷连接模块；一根包含八条信号的线缆即可自动按标号匹配。也支持贴在主板旁，使用接触面的 G1 同名引脚。接线不足或断线时屏幕熄灭，两种极性均如此。

段位顺序为 `bit0=A, bit1=B, bit2=C, bit3=D, bit4=E, bit5=F, bit6=G, bit7=DP`。共阴数字 0–9 的段码依次为 `3F 06 5B 4F 66 6D 7D 07 7F 6F`；置位 bit7 点亮小数点，共阳将整个字节取反。直接写段电平，可显示十六进制字形、自定义图形或逐段测试，不需要 I²C 控制器。

烧录 `examples/seven_segment_counter.hex` 可循环显示 0–9，奇数时同时点亮小数点，默认晶振下约每 0.55 秒切换一次。`30H` 保存当前数字，`31H` 保存输出段码。附带 `seven_segment_counter.c` 供 Keil C51 修改；随附 HEX 由项目脚本汇编生成，C 源码中的软件延时会随 Keil 优化设置变化。

生存合成：在工作台中间放一块**覆铜电路板**，周围八格放 **LED 模块**。游戏内手册包含接线、段码和示例章节。显示模块放置时朝向玩家，随方向旋转显示；共阳/共阴设置随世界保存。

## 独立 OLED 模块

OLED 是单独的方块，包含自己的 SSD1306 控制器和 1024 字节显存。右键只打开独立的 OLED 放大查看窗口，不跳转到主板烧录界面。模块显存、显示开关、寻址和扫描状态随模块自身保存。

### 推荐演示：通过 I²C 显示文字

1. 在主板任一侧放置 OLED。
2. 在主板的相邻面添加两个 **GPIO** 引脚，分别设为 **SDA=P1.6** 和 **SCL=P1.7**，再点击「应用」。OLED 会按标号自动连接。
3. 烧录 `examples/i2c_oled_hello.hex` 并运行。
4. OLED 显示 `EMBEDDED DEV`、`STC89C52`、`HELLO MINECRAFT`、`I2C 0X3C`。右键 OLED 可放大查看。

`oled_pattern.hex` 是早期的原始显存条纹诊断图，里面没有文字；看上去像乱码是因为发送的就是交错位图。新版可读示例均使用软件 I²C，分别是 `i2c_oled_hello.hex` 和 `oled_hello.hex`。

I²C 七位地址 **3Ch**，写地址字节 **78h**。支持 START/STOP、重复 START、地址匹配、ACK/NACK、控制字节的 Co / D-C、页寻址、水平/垂直寻址、列/页范围、显示开关、反显、全亮、扫描方向、起始行和显示偏移。常见初始化中的对比度、充电泵、时钟等设置可以接受，但不会模拟面板电气特性。滚动命令可接收，目前不产生滚动动画。不模拟 SPI、多主仲裁或时钟拉伸。

I²C 是基于虚拟 GPIO 边沿的逻辑仿真，不做模拟电压或严格总线速率校验。通用 SSD1306 驱动需要使用所绑定的两根 GPIO，采用 128×64 / 3Ch 配置；不同屏幕芯片或额外外设的驱动仍需要对应设备实现。

### MCU 内存与 OLED 显存

1.10.1 起删除 MOVX 桥接。原 F020H 与 F100H–F4FFH 均为普通 XRAM，写入不会控制、清除或改写 OLED。3Ch 是 I²C 总线地址，不是 MCU 内存地址。OLED 的 1024 字节显存属于模块；固件若自行分配帧缓冲，该缓冲区才占 MCU RAM。

旧桥接版 `oled_hello.hex` 和 `oled_pattern.hex` 需要重新烧录新版文件。两个新版示例均已使用软件 I²C；已有原生 I²C 程序可继续使用。旧模块的画面和控制器存档保留。世界面板最多每 4 tick 同步一次，模块窗口每 5 tick 刷新。

## I²C 环境传感器

将 **I²C 环境传感器** 贴在主板旁，在相邻面添加标号为 SDA 和 SCL 的两个 GPIO。七位地址 **48h**，写地址 **90h**，读地址 **91h**。

先写入寄存器编号，再用重复 START 切到读操作，读取后地址自动递增。无效寄存器返回 FFh。

| 寄存器 | 读数 |
|---|---|
| 00h | 模块周围除主板外的最大红石强度，0–15 |
| 01h | 模块上方天光，0–15 |
| 02h | 模块上方方块光，0–15 |
| 03h | 一天的进度百分比，0–99 |

`examples/i2c_sensor.hex` 用 SDA=P1.6 / SCL=P1.7 读取寄存器 0，保存到 IDATA 30H，并用 P1.2 指示是否非零。另一线组添加 `LED=P1.2`、连接 LED 模块即可观察。右键传感器可查看原始读数。

## 按钮、LED、DS1302 与 PCF8591

将模块放在开发板旁，在接触面添加以下同名 **GPIO**，然后应用配置。

| 模块 | 端子 | 操作 |
|---|---|---|
| 按钮面板 | `KEY`、`KEY2`–`KEY9`，可改名 | 空手右键对应键拉低 10 tick。读取前释放对应 MCU 端口锁存位 |
| LED | `LED` | 写 1 点亮，写 0 熄灭 |
| DS1302 | `CE`、`SCLK`、`IO` | CE 拉高开始传输，命令和数据低位先行 |
| PCF8591 | `SDA`、`SCL` | 默认七位地址 48h，潜行右键循环 48h–4Fh |

空手潜行右键按钮面板，或右键面板上没有按键的位置，可设置 1–9 个按钮和各自的标号。主板端子添加相同标号的 GPIO，再用线卷依次点主板端子和具体按钮。每键单独接一根线，已连接的线缆在手持其他物品时也能看到。旧按钮保留在中央，原 `KEY` 线可继续使用。改名保留物理接线，减少数量会拆除被移除按键的线并掉落对应线材。

DS1302 支持 BCD 日历、时钟停止位、写保护、31 字节 RAM 和突发读写。读秒用 `81h`，读日历用 `BFh`。时钟随世界 tick 推进，时间和 RAM 随模块保存。

PCF8591 的 AIN0–AIN3 按北、东、南、西取样，将红石强度 0–15 映射到 0–255。读取首字节为上一次转换，读取第二字节取得当前通道数据。控制字位 6 使能 DAC，AOUT 从模块上面输出 0–15 红石强度。与同一总线上的 48h 环境传感器共用时，可将 PCF8591 改到 49h。

## DS18B20 温度探头

将探头贴着被测设备的任意一面放置，探头会读取接触的那个方块。给主板任意线组添加 **GPIO `DQ`**，用线卷接到探头。支持标准速率 1-Wire 复位/存在脉冲、Skip/Match/Read/Search/Alarm Search ROM、Convert T、Scratchpad 读写、Dallas CRC8，以及配置 EEPROM 保存。量程 **-55～125 ℃**，9–12 位分辨率，12 位转换需最多 750 ms。读输入前释放 GPIO，数据按低位先行传输。

温度来源按已接入的接口选择。

- **Mekanism** 从 `mekanism:heat_handler` 读取接触侧的热容温度，开尔文减 273.15 转为摄氏度。
- **Create 锅炉** 从多方块控制器读取 `ActiveHeat`/`PassiveHeat`。本模组将活跃热量 0–18 级映射为 `20 + 5 × 等级` ℃，被动加热为 60 ℃，停热为 20 ℃。右键明确显示「Create 热量折算」。此换算为模组的游戏温度模型。 [Create 锅炉数据](https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/content/fluids/tank/BoilerData.java)
- 原版燃烧中的熔炉为 90 ℃，营火为 95 ℃，岩浆块为 110 ℃，熔岩源温度设为 1000 ℃并触发探头超量程提示，冰雪为 0 ℃，其余使用群系环境模型。
- 其他模组可注册 `embeddeddev:temperature` 方块能力，返回 `TemperatureProvider`，或由方块实体实现该接口，提供摄氏度读数。

空手右键探头可查看温度、来源和量程状态。超量程时 GPIO 读数限制在 -55～125 ℃。在 **12 MHz** 晶振下运行 `examples/ds18b20_read.hex`，将 `DQ` 绑定 `P1.2`。固件完成一次转换后，把含 CRC 的 9 字节 Scratchpad 存入 IDATA `30H–38H`，`3FH=A5H` 表示结束。温度为有符号的前两个字节除以 16。同目录提供 Keil C51 源码，HEX 由项目汇编生成器生成。

## 程序与示例

Keil C51 建议 SMALL 内存模型、11.0592 MHz、勾选 Create HEX File。代码地址限制在 0000h–1FFFh；全部 64 KiB XDATA 为普通 RAM，外设不再保留内存窗口。

| 文件 | 接线要求 |
|---|---|
| `redstone_blink.hex` | 将 GPIO P1.2 接到设为输出的红石端子，约每 0.5 秒切换 |
| `pcf8591_mirror.hex` | PCF8591 默认地址 48H，SDA=P1.6、SCL=P1.7；北面 AIN0 → 上面 AOUT |
| `i2c_oled_hello.hex` | OLED 所在面添加 GPIO，SDA=P1.6、SCL=P1.7 |
| `oled_hello.hex` | 同上，软件 I²C 显示文字 |
| `i2c_sensor.hex` | 传感器所在面添加 GPIO，SDA=P1.6、SCL=P1.7，另一线组 LED=P1.2 |
| `ds18b20_read.hex` | DQ=P1.2，安装 12 MHz 晶振，读取温度探头 |
| `seven_segment_counter.hex` | A–G、DP 依次绑定 P1.0–P1.7，共阴模式显示 0–9 |
| `oled_pattern.hex` | 软件 I²C 诊断条纹，不是文字示例 |

同名 C 源码、`i2c_soft.h`、`embeddeddev.h` 和原始字模在 `examples` 中。HEX 为功能等价的手写机器码示例，当前环境没有用 Keil 编译这些 C 文件。`tools/generate-firmware.mjs` 可重现新的 HEX 和字模；`tools/generate-models.mjs` 可重现立体模型资源。

| XDATA 地址 | 功能 |
|---|---|
| F000h–F007h | 普通 XDATA RAM（1.10.0 起释放） |
| F010h–F017h | 普通 XDATA RAM（1.10.0 起释放） |
| F020h、F100h–F4FFh | 普通 XDATA RAM（1.10.1 起释放） |

HEX 从客户端本地读取，只上传固件内容，服务端不读取玩家的路径。解析检查记录长度、校验和、EOF、地址范围和冲突覆盖；全部成功后才替换旧程序。支持 Intel HEX 00–05 记录、8 KiB 程序和最大 128 KiB HEX 文本。

## CPU 与存档

支持 8051/8052 全部 255 个已定义基础操作码、256 字节 IDATA、独立 SFR、四组寄存器、位操作、MOVC/MOVX、乘除、BCD 调整、双 DPTR、Timer 0/1/2、标准 IE/IP 两级优先级中断、Idle 和 Power-down。提供完整的 64 KiB 普通 XDATA RAM，无外设保留窗口。A5h 保留操作码会停止执行并显示故障。

UART 是虚拟控制台，写 SBUF 会立即输出并置 TI。STC 特有的四级中断优先级、额外中断源、看门狗、IAP/EEPROM、6T/1T 加速、Timer 2 专用波特率/向下计数模式，以及真实电气/外部总线时序尚未实现。

区块卸载后 CPU 暂停，不补跑离线时间。CPU、RAM、固件和接线随主板保存；OLED 随模块自身保存。I²C 正在进行的传输在加载或改接线时重新同步，固件应为新事务发送 START。破坏主板掉落空白主板；破坏 OLED 掉落空白模块。比较器可读取主板运行状态（运行 15，停止 0）。

默认每 tick 执行的机器周期按晶振频率除以 240 计算，对应 20 TPS 下的 12T 时序。服务器配置 `embeddeddev-server.toml` 的 `cyclesPerTick`（256–100000）以 11.0592 MHz 为基准，其他晶振按频率比例缩放。

## 构建与验证

```powershell
.\gradlew.bat build
.\gradlew.bat verifyMcu
.\gradlew.bat verifyHandbook
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
```

`build` 会运行 CPU/HEX、接口/I²C 和双语手册回归检查，包括多引脚接线、共享总线、地址 NACK、重复 START、ACK/NACK、SSD1306 寻址及所有示例固件。新增真实 MOVX 遍历整个 64 KiB XDATA 的读写和存档检查，确认 OLED 连接时也不会覆盖 RAM、清屏或改变控制器状态。GameTest 验证旧 ADC/DAC 配置迁移暂停且保留 GPIO、红石方向、远程接线存档、OLED 独立存档和固件 I²C 控制。测试类及测试结构不打入发布 JAR。

Windows/JDK 若因默认 socket 临时目录导致 `Unable to establish loopback connection`，可在当前 PowerShell 临时设置：

```powershell
New-Item -ItemType Directory -Force build/socket-tmp | Out-Null
$env:JAVA_TOOL_OPTIONS = '-Djdk.net.unixdomain.tmpdir=' + (Resolve-Path build/socket-tmp).Path
.\gradlew.bat build --no-daemon
```

模拟通道、连接规则和环境传感器寄存器为本模组约定。参考资料包括 [STC89 数据手册](https://www.stcmicro.com/datasheet/STC89C51RC-en.pdf)、[DS1302 数据手册](https://www.analog.com/media/en/technical-documentation/data-sheets/DS1302.pdf)、[PCF8591 数据手册](https://www.nxp.com/docs/en/data-sheet/PCF8591.pdf)、[SSD1306 数据手册](https://cdn-shop.adafruit.com/datasheets/SSD1306.pdf)及 [NXP I²C 总线规范](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。

## 独立传感器、多通道电机接口与驱动附录

新增 MPU6050 惯性传感器（68H/69H）、ALT-01 高度计（76H）和多通道电机接口（60H–67H）。它们均通过现有线缆连接普通 GPIO 软件 I²C。每块电机接口只控制其六个紧邻面上的创造马达，六路有符号 RPM 原子提交并带看门狗；八个地址可提供 48 路。MPU6050 和高度计不依赖机械动力，Sable 为可选运动数据来源。

手册新增独立「附录」分类，提供 11 组驱动、40 份完整 .h/.c（包含最小主程序），从 examples/drivers 逐字生成，可按文件复制。覆盖软件 I²C、MPU6050、高度计、电机接口、PCF8591、环境传感器、按钮/LED、红石、数码管、DS1302、DS18B20 和 SSD1306。详见 [驱动源码使用说明](../examples/drivers/README.md)。

详细寄存器与开发说明见 [独立模块与驱动手册](modules-and-drivers.md)。
